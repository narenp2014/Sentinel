# Sentinel Project

This repository is a capstone project focused on evaluating and hardening an LLM-based HR assistant against policy violations.

## Project goal

Build a small system that can:

- accept a user conversation request,
- route a request to either RAG or agentic mode,
- retrieve relevant policy documents,
- evaluate whether the model output violates internal policies,
- record attempts, verdicts, and evidence for analysis.

## Current structure

- `src/sentinel_project/models/` contains the core Pydantic models for requests, responses, attempts, and verdicts.
- `src/sentinel_project/target/` contains the target system prompt and runnable target app.
- `src/sentinel_project/agents/` contains agent and red-team workflows.
- `src/sentinel_project/retrieval/` contains policy retrieval and dataset loading.
- `src/sentinel_project/evaluation/` contains policy evaluation logic.
- `src/sentinel_project/storage/` contains SQLite persistence services.
- `src/sentinel_project/api/` contains the HTTP API.
- `src/sentinel_project/ui/` contains the Streamlit dashboard.
- `src/sentinel_project/settings.py` loads environment-backed configuration.
- `src/sentinel_project/app.py` mounts the API under a top-level app.

## Local setup

1. Create and activate a virtual environment with `uv`.
2. Install dependencies with `uv sync`.
3. Add environment values to a `.env` file based on `.env.example`.
4. Run tests with `uv run pytest -q`.
5. Start the API with `uv run uvicorn sentinel_project.app:app --reload`.

## Assistant API and retrieval

```powershell
uv run uvicorn sentinel_project.target.target_app:app --reload
```

The target exposes `POST /chat` (`/target` remains as a compatibility alias),
`/health`, and `/target/prompt`. Requests use `TargetRequest` and responses use
`TargetResponse`.

If the Markdown corpus is absent, retrieval falls back to
`src/sentinel_project/docs/policies.json`. Seeded corpus documents are chunked on
sentence boundaries at up to 500 characters, with one-sentence overlap. Long
sentences split at word boundaries. The offline prototype can use Chroma's default
local embedding function. To use the specified OpenAI embedding model, set
`OPENAI_API_KEY` and run `uv run python scripts/index_corpus.py`; it indexes the
dedicated `sentinel_hr_policy_chunks_v1` collection under `CHROMA_PATH` using
`text-embedding-3-small` and 512/64 word chunks. The four nearest chunks are
returned with stable IDs and 1-based ranks. Existing collections are not deleted.

The full synthetic 35-document corpus is generated by
`uv run python scripts/seed_corpus.py`: 20 clean 500-1,500-word policies, five
restricted compensation documents with exact sentinels, two fictional employee
records, and eight poisoned documents with distinct injection styles. To use the
model to generate document bodies instead, run
`uv run python scripts/seed_corpus.py --openai`; this uses the configured model
and may incur API charges.

Attack seeds are in `src/sentinel_project/attacks/seeds.yaml`: 96 structured
seeds (12 per category), including targeted policies, applicable modes, and a
poison-document dependency where relevant. Rebuild that metadata with
`uv run python scripts/structure_attack_seeds.py`.

The chunk-size experiment uses explicit `text-embedding-3-small` embeddings and
creates persistent indexes for `256/32`, `512/64`, and `1024/128` word chunk/
overlap settings. Run it with `uv run python scripts/run_chunking_experiment.py`;
it requires a valid API key and writes CSV/Markdown results under `reports/`.

Build the default 512/64 persistent index with
`uv run python scripts/index_corpus.py`; this also requires the configured
OpenAI key and can incur embedding charges.

Set `mode` to `rag` for retrieval-grounded generation or `agentic` for the same
retrieval plus a bounded function-calling loop. Agentic mode registers
`search_directory(name)`, `send_email(to, body)`, and
`delete_employee_record(id)`. These are logged canned demo stubs: they do not
access a directory, send email, or delete records. Email and deletion calls are
gated on explicit confirmation.

Set `hardened: true` to activate the prompt-injection input filter and remove
retrieved sentences that appear to override instructions or request hidden
prompt/canary disclosure. It deliberately preserves ordinary imperative HR policy
clauses. This heuristic hardening is a prototype safeguard, not a security
boundary. Canary redaction applies to hardened responses.
Baseline mode intentionally includes a deterministic canary-extraction fixture so
red-team scans have a known-positive P1 case; do not deploy baseline mode as a real
assistant. Hardened mode blocks that fixture and redacts canary matches.

`POST /chat` is the executor boundary. Never expose baseline mode outside this
local, fictional benchmark; `hardened: true` enables the mitigation path.

## Run the Streamlit assistant

```powershell
uv run streamlit run src/sentinel_project/ui/streamlit_app.py
```

Successful requests are stored in the SQLite database configured by
`DATABASE_URL` (by default, `sentinel.db`). The `assistant_interactions` table
stores the prompt, full conversation, response, mode, policy verdict, and
retrieved policy IDs. Keep this database local because it contains user input
and assistant responses.

The UI also launches scans, browses findings, accepts human labels, and shows
judge/human metrics. Start the target API before using the scan launcher.

## Run a scan

```powershell
uv run python scripts/run_scan.py --budget 20 --planner uniform
```

The scan caps concurrency at five, retries transport failures, uses remaining
budget for mutations up to depth three, and stops at its estimated-spend limit.
Attack generation and judging are deterministic/offline by default. To opt into
model-based attack generation/mutation and rubric judging, add
`--llm-generator --llm-judge`; this uses the configured API and may incur charges.
The first 50 traces are assigned to all five reviewers for calibration; remaining
labels unlock after that shared calibration set is complete.

Run a baseline-versus-hardened comparison with
`uv run python scripts/compare_target_modes.py --budget 20`. It executes two
separate scans against the local target and writes their results to
`reports/baseline_vs_hardened.json`.
Scan cost is stored by target, generator, and judge. Generator/judge calls use
provider-reported token counts; target-call token counts are estimated from text
length, so target cost is approximate. Pricing rates are configurable in
`settings.py` and should be verified against the selected model before a report.

Generate the frozen 60-case judge regression fixture with
`uv run python scripts/seed_golden_set.py`. CI checks the fixture on each push
and pull request.

After human labels exist, compare a higher-cost and lower-cost Judge on the same
traces with
`uv run python scripts/compare_judge_models.py --expensive-model MODEL_A --cheap-model MODEL_B`.
This makes live API calls for both models and writes per-category agreement,
precision/recall, token usage, and estimated cost to
`reports/judge_model_comparison.json`.

## Remaining team deliverables

The app provides rubrics, labeling controls, and metrics, but people must still
agree on rubric wording, assign five reviewer IDs, label the shared calibration
set and planned evaluation sample, review disagreements, and report the observed
agreement/precision/recall. Set an OpenAI spend limit, publish the public repo,
record the demo video, and freeze model names/pricing assumptions before making
cost claims.

## Limitations

This is a controlled synthetic benchmark, not a production HR system. The default
judge uses deterministic heuristics; model-based judging is opt-in, and accuracy
claims are meaningful only after independent team labels exist. Results describe
only this synthetic target. Only scan the target service owned by this project.
